# Image replacement

Open **Image replacement** in the left sidebar. It has its own saved draft. **Image model** selects the Klein baseline or the Qwen 2.1 trained whole-person evaluation recipe. The current rental has Qwen installed in place of Klein. Changing the model never starts a download. Neither image recipe loads Viggle, SCAIL, SAM or video LoRAs.

1. Add a **target photo** and an **identity reference**. The target supplies composition, pose, apparent head/body size, camera distance, expression and scene lighting; the reference supplies the replacement's face, hair and outfit.
2. To edit a frame from the current video, choose **Use motion frame**. The original video ID and exact 24 fps clip time are retained. **Use motion character** copies the selected character into the separate image draft.
3. **Protect the background** is on by default. Paint over the original person, hair, clothing and relevant contact shadows. Leave foreground occlusions unpainted. Paint, erase, undo and brush size work locally; saving stores a grayscale mask bound to this target.
4. Keep the photographic replacement prompt or refine it. Clearing it activates the same default. The fixed image-role instructions remain: target first, identity second. Only Klein accepts an optional third face close-up.
5. For Klein, automatic face detail uses the existing local YuNet detector to crop an unambiguous reference face. An optional uploaded close-up can replace that crop. This is conditioning and visual review, not face recognition or an identity guarantee. The experimental BFS head pass is off by default: live tests still showed identity drift and visible hair seams. Qwen's whole-person recipe follows its trained two-image contract and does not silently add the Klein head adapter or a third reference.
6. Download only the files required by the selected image model, then **Replace character**. Image and video jobs share one queue, so an existing video is never interrupted to run an image. The result displays its actual saved base/reference inputs, even when the current draft has changed.
7. Review **Compare** and **Face review** before using the result. Download a lossless PNG or open **My library**. Head position/size warnings are diagnostics; there is no fabricated facial-similarity percentage or automatic quality rerender.

Klein uses `flux-2-klein-4b-fp8.safetensors`, `qwen_3_4b.safetensors` and `flux2-vae.safetensors`, totalling **12,451,817,860 bytes**. They are required by Viggle's **automatic** source-frame preparation, but a video using an **already edited source frame** skips them. At the user's explicit request, these files and the experimental Klein head adapter were removed from the current rental to make room for Qwen. All four Viggle files were retained.

The baseline Klein recipe uses **four Euler steps, CFG 1**, with a reproducible saved seed. A random seed changes the seed for the new job only. No beautifier, face-restoration model, hidden quality rerender or paid image API is applied. The explicit experimental head option adds a second four-step stage and one 369,644,384-byte matching 4B adapter. These stages report their actual sampler counters. Klein components are Apache-2.0; see [Black Forest Labs' Klein release](https://bfl.ai/blog/flux2-klein-towards-interactive-visual-intelligence). The [BFS adapter guide](https://huggingface.co/Alissonerdx/BFS-Best-Face-Swap/blob/main/docs/flux-2-klein.md) specifies base/body first and reference face second; its weights are MIT.

Klein working detail is capped at one or two megapixels without upscaling a smaller target. For a tight close-up target and distant body reference, the new recipe crops only the reference's field of view using detected face geometry; it never stretches the person or alters the original input. Qwen generates at the selected one/two-megapixel working area on its 32-pixel grid. Both uniformly preserve aspect ratio, remove only padding and restore the original target dimensions. Upsampling a conditioning photograph does not create missing identity information.

New masked **Klein** jobs encode the target as the starting latent and apply the source-aligned edit mask during sampling, then composite the result into the original photo. Qwen follows its trained native scene-sized latent recipe and applies the mask during final compositing; that mask does not constrain its denoising trajectory. The earlier composite-only recipe allowed Klein to redraw a brighter background inside a broad painted region, producing an obvious pale halo. The masked-latent correction substantially reduced that defect in a same-input GPU test, but did not eliminate all changes to background painted inside the mask.

Feathering is inward, so zero-mask pixels never admit generated content. Local PNG finalization restores exact decoded source pixels outside the mask, removing float-to-PNG rounding differences. The guarantee applies **outside the mask**, not to background painted inside it, identity, pose or anatomical accuracy. Fine masks and an appropriate reference still matter. Paid legacy jobs retain their original conditioning recipe on recovery.

The first live evaluations are **not a quality pass**. The general four-step editor blended facial features and retained pieces of the target outfit. A focused clothing instruction transferred the full dress more successfully, but facial likeness remained insufficient. Do not treat automatic face crops or a long preservation prompt as a trained identity constraint. See [the validation record](validation/image-replacement-20261027.md).

## Qwen whole-person evaluation

The Qwen option uses its matching INT8 transformer, Qwen3-VL 8B INT8 encoder, RGBA VAE, official eight-step acceleration adapter and **BFS Body Swap V1.0 for Qwen Image 2.1**. Its full pinned download is **18,406,159,200 bytes**. The graph uses eight Euler/simple steps, CFG 1 and reference-prefix caching at default precision. The first reference and the native latent output both come from the base scene. A separate RGB split handles the Qwen VAE's alpha channel before final masking. No prompt-enhancer model is required.

The [body adapter's guide](https://huggingface.co/Alissonerdx/BFS-Best-Face-Swap/blob/main/docs/qwen-image-2.1-body.md) explicitly transfers the reference person's face, body appearance and clothing while following scene pose, framing and lighting. It recommends a clear front-facing full-body reference on a plain light background and approximately 0.59 MP reference area. Studio follows that reference budget without cropping it into a portrait. It does not automatically normalize a portrait into an invented full-body person. The training task matches whole-person replacement, but that does not guarantee the requested identity, pose or lighting on arbitrary photos.

The complete stack is now SHA256 verified and tested on the existing **A100 PCIe 40 GB**. After waiting for the active video to finish, the authorized Klein removal reclaimed **12.82 GB**; Qwen and Viggle fit together on the same **64 GiB** disk, with **14.18 GB free** after the tests. Keeping both image stacks would require more space. Bulk-download preflight still reserves 5 GiB of working space, accounts for retained partials and blocks an insufficient-space plan before starting workers. All downloads remain explicit actions.

The exact latest target/reference/mask produced an image in **45.873 seconds**. A second run with a close-up framing instruction took **40.033 seconds**. The reference face and black outfit transferred more clearly than in the Klein baseline. The first run generated an extra arm and made the head much smaller; the focused instruction removed that extra arm and improved framing, but the head remained about **0.76×** the target size by face-box geometry. Outdoor light, broad mask edges and small unpainted holes remained visible. **Neither output passes the requested photographic-consistency standard.** Both are saved in the library; neither was automatically used for video. Peak VRAM was not continuously measured, so successful execution on 40 GB is the supported claim. See [the migration and test record](validation/qwen-migration-20261027.md).

At this host's reported $0.004/GB ingress rate, an 18.41 GB first download is roughly $0.074 in transfer fees, separately from compute and storage. At the configured $0.005/GB host limit it is roughly $0.092. The Qwen download is complete. The two measured image runs correspond to about **$0.0087** of combined compute/storage time at the current rate. These are estimates from measured duration and provider quotes, not itemized billing receipts; downloading time, setup and idle time also cost compute. Existing media and video weights were retained.

Qwen components use the Qwen Research License, and the BFS body adapter is MIT. Private evaluation and a future hosted commercial service are separate licensing questions. The source guide records approximate pose following and reduced likeness for small faces; it does not promise an identity lock.

Completed GPU receipts are saved before image download. Reconnection checks the same prompt and its history. Once downloaded, failed local finalization can be retried even with the GPU offline, without resampling. A genuinely missing paid GPU output requires the explicit existing retry action; it is never silently submitted again.

## Return to video

**Use in Motion control** saves the PNG as a reusable input. If the target was extracted from a known video, it restores that video and clip start, uses native 24 fps and selects **prepared frame**, avoiding a second Klein edit. A generic photograph becomes a normal character reference with **automatic preparation**; it is not mislabelled as a frame from an unrelated video. Review likeness before propagating it: video conditioning cannot repair an incorrect identity anchor.

Viggle's **Reference preparation** menu disables **Automatic** unless all three Klein files are confirmed installed. Its adjacent download button can restore Klein explicitly when the GPU is connected and the disk has sufficient free space. It shows the required-space reason when disabled. A missing or unknown installation does not silently turn an ordinary reference into a prepared frame. The server also rejects automatic jobs with missing Klein before queuing a paid render. The prepared-frame option uses only Viggle's own model stack and remains available without Klein.

The portable editable examples are [full-photo editing](../workflows/experimental/klein4b_image_replacement.json) and [masked editing](../workflows/experimental/klein4b_image_masked.json), with matching API graphs beside them. They use a 1024-square target. Studio's per-job export contains the actual source dimensions, mask, uploaded filenames and optional face input. Regenerate the examples with:

```sh
cd studio
npx tsx scripts/export-image.ts
python3 ../scripts/build_image_workflows.py
```

## Model research · 27 October 2026

| Model/path | Evidence and suitability | Decision |
|---|---|---|
| FLUX.2 Klein 4B FP8 | Native multi-reference editing; four-step distilled recipe; shared with automatic video preparation. Removed from the current rental at the user's request. | Baseline tests failed the required fidelity. Remains an explicit download option. |
| FLUX 3 Image Klein 5.6B | New open-weight release with multi-reference editing and bounding-box guidance. BFL reports stronger editing scores than its earlier 9B model, but these are publisher evaluations, not our matched face-swap tests. | Best next small-model comparison candidate. It is a different model/encoder/schedule, not a replacement filename in the current graph. |
| Qwen-Image 2.1 + BFS Body Swap | Matching native Comfy nodes and the pinned eight-step stack ran on the current 40 GB GPU. | Installed. Same-input tests improved visible face/outfit transfer but failed exact scale, lighting and mask-edge fidelity. |
| Qwen-Image-Edit-2511 | Publisher documents improved character consistency over 2509 and Apache-2.0 licensing. | Older fallback; do not install its separate large stack merely from generic editing claims. |
| Community PuLID-Flux2 | Identity embeddings and cross-attention injection are attractive, but inspected code includes silent no-face bypass and randomly initialized fallback paths when dimensions differ. | Do not ship it as an “identity lock” without validating compatible trained weights, repeat-run behavior and dependency licensing. |

[BFL's FLUX 3 release](https://bfl.ai/blog/flux-3-image-klein/) and [its Comfy model card](https://huggingface.co/black-forest-labs/flux-3-image-klein-comfy) specify a 16-step distilled recipe, a separate Qwen3-VL encoder and scene-caption prompting. The INT8 transformer is listed at 5.8 GB, the INT8 encoder at 4.9 GB, plus the shared 0.3 GB VAE. Their default prompt upsampler is another 9.8 GB in INT8 or 6.7 GB in W4A8; an appropriate external captioner is also supported. Bounding boxes guide layout but are not hard pixel masks. Access is gated and the FLUX Kommunity License has specific qualifying-commercial-output terms; it is not Apache-2.0.

[Qwen's 2.1 model card](https://huggingface.co/Qwen/Qwen-Image-2.1) documents the multi-reference and editing capabilities, CPU offloading and Qwen Research License. [The 2511 card](https://huggingface.co/Qwen/Qwen-Image-Edit-2511) documents its separate editing architecture and Apache-2.0 licence. These models cannot use Klein's Qwen3 text-only encoder simply because their names contain “Qwen.” The [PuLID implementation inspected](https://github.com/iFayens/ComfyUI-PuLID-Flux2/blob/main/pulid_flux2.py) is community code; its claims are not a matched quality benchmark.

Selecting a model never downloads weights. The user explicitly authorized the Qwen migration and its two same-input tests. A new stack should earn its storage, transfer and setup costs in a same-input comparison before becoming a general default. No open-weight model cited here establishes zero identity drift or equivalence to a closed image service on arbitrary inputs.
