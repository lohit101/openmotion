# Post-processing and output frame rate

The sidebar now has **Post-processing**, with **Fix Faces** and **Smooth Motion**. Fix Faces keeps the copied OpenJutsu model, face styles, small-face skip, settings and graph. Remotion's existing shortcut opens it in the new workspace. Each tool keeps its own saved inputs and settings.

Smooth Motion accepts an uploaded SDR video or a completed Library result, up to five minutes and 4096 pixels per edge. Choose 30, 48 or 60fps. First use shows **Download Smooth Motion** in the usual action footer: one pinned RIFE 4.25 weight, **22,674,688 bytes**, plus a small local node package. It uses the existing managed engine and native ComfyUI RIFE implementation; it does not need the H3 video weights. Downloads use the same Xet/resume/checksum/inventory/deletion controls as other models. Generate never provisions files or starts compute. Explicit first-use preparation may restart the owned, idle ComfyUI engine to register the node; unrelated engines, active queues and locally edited files remain protected.

In **Remotion → Scene & output → Output frame rate**, choose 24fps Original, 30fps, 48fps or 60fps. Existing drafts/runs remain at 24fps unless changed. A higher choice includes Smooth Motion in Download Remotion's selected dependencies. The H3 graph still renders at 24fps and is saved unchanged; the same job then uploads that exact saved result to the finishing node. The final preview/download uses the requested frame rate, while **Original 24fps** downloads the retained native video. There is one overall progress lifecycle, and the GPU stays busy through finishing.

If using Clarity or Fix Faces, the efficient order is **24fps Remotion → Fix Faces if needed → Clarity if needed → Smooth Motion**. Increasing FPS before those tools makes them process extra frames. Remotion's automatic option is useful when its generated resolution is the desired final resolution. Face correction and upscaling remain explicit operations; selecting an output frame rate does not silently enable them.

The finishing worker samples the original clock at exact rational output timestamps. It asks RIFE only for needed intermediate frames, rather than generating an oversized sequence and dropping most of it. Frames and model features stay bounded to a few neighboring frames. There is no hidden image resize; padding is removed before encoding. Detected cuts hold the old shot until the original boundary instead of synthesizing a transition. Phone display rotation is baked into the output geometry. Variable input timing is conformed to its measured average rate before interpolation. The endpoint can hold the last source frame within its original display interval; output duration differs by at most one output frame. Odd pixel dimensions, HDR and unsupported rotations produce actionable errors.

Export is high-quality H.264 at CRF16, not a lossless video encode. Compatible existing audio is copied, including native H3 AAC; unsupported MP4 audio codecs are encoded as AAC. No new speech is generated, and playback speed/pitch do not change. Interpolation targets smoothness rather than identity, teeth or expression repair, and rapid occlusions may still show artifacts. Cut detection is conservative and is not a universal shot detector.

Standalone processing creates a separate Library result; its source/parent stays immutable. Automatic finishing retains both native and finished files in the same run. Each phase freezes its own graph/hash, source hash and completion/failure receipts. A lost acknowledgement observes the same request rather than submitting twice. A completed native history can finish downloading without inference; a saved finishing file can finish locally offline. Terminal finishing errors expose **Retry finishing · uses GPU**, which requires an explicit retry and preserves the failed receipt. It never reruns the already-saved H3 generation. Cancellation uses the existing exact-request ComfyUI cancellation path and closes the worker's own FFmpeg processes.

Validation: 724 Studio checks, 419 Python checks (one existing skip), final focused checks, typecheck and production build pass. Local CPU execution used the real pinned RIFE weights and the pinned ComfyUI IFNet source at all three output rates; only device-allocation/node wrappers were substituted. Synthetic one-second exports have exact frame counts, identical copied AAC packets and reusable receipts. Additional FFmpeg checks cover cut timing, phone rotation, downsampling, cancellation and short reads. GPU/CUDA speed and human-video visual quality have not been benchmarked, and native browser review was unavailable under the existing computer-use restriction.
