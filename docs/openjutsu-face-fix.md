# OpenJutsu Fix Faces

In Remotion, open a completed video and choose **Fix Faces**, or open **Post-processing · Fix Faces** and upload a finished video. Choose the same character photo used for the video. The finished parent stays immutable; the correction creates a separate Library result.

**Match the photo** prioritizes the photo's likeness but lets H3 redraw the expressions and mouth. **Follow the mouth** supplies the native blurred motion reference to retain the video's facial performance, with potentially weaker likeness. The default is Match the photo, as in the Desktop project. Native behaviour leaves faces taller than one-fifth of the frame alone. There is no new override to force large close-ups through this small-face workflow.

The original `face.ts` and 30-node `face.api.json` are vendored byte for byte. Both default submitted graphs match independently compiled Desktop fixtures after the same media bindings, detector-path normalization and soundless-video adapter. Tracking, 512px crops, smoothing, SAM masks, one-second chunk overlap/crossfade, colour matching, feather8, H3 model/sampler and CRF16 export remain native. Recast adds job ownership, input hashes, parent binding, saved history and transfer recovery; it saves the native MP4 without another encode. Legacy PerformRecast/FaceFusion/repair stages are not attached.

First use offers **Download Fix Faces**. It reuses six H3 components and adds five pinned files totalling **673,203,772 bytes**: two YOLO detectors, SAM ViT-B and Buffalo-L's detection/recognition models. Only the two InsightFace modules requested by the original node are installed, under its expected model-pack directory, so inference need not download a pack. Missing files block generation. Runtime installation is explicit, requires an idle connected managed GPU and retains the queue/changed-tree guards. It adds pinned FaceRefine, Impact Pack and Impact Subpack plus their Python dependencies; setup uses the configured private port and installed Python environment. Face files remain individually deletable and return through the same download action.

The copied application code is MIT. Impact Pack/Subpack, Ultralytics and the pretrained InsightFace models have separate terms, including non-commercial research restrictions for the recognition weights. This integration does not clear a hosted commercial service.

Validation covers native graph parity, minimal downloads, immutable parents, separate drafts, missing weights, exact output transfer/recovery and physical inventory for files not exposed in loader lists. Full GPU face quality, latency and cross-clip stability remain for user validation. The native browser review was blocked when computer use became unavailable for the current browser URL; no final visual pass is claimed. ## Setup recovery, 2026-11-07

The first live face setup exposed SAM2 build isolation pulling a duplicate PyTorch build environment. Face dependency installation now reuses the existing constrained PyTorch, Cython and build tools; SAM2’s optional CUDA extension is disabled because this graph uses SAM1. A separate closing-socket race made the completed setup’s immediate engine restart fail. Managed tool preparation now waits up to ten seconds for the old private port to close, preserving refusal to replace an unknown listener. The same rental was recovered and the explicit module retry reports Ready. All fifteen preparation regressions pass; no inference or model-weight redownload was needed.
