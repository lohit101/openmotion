# Xet model downloads

The normal module and Settings download buttons now use Hugging Face's Xet client for pinned Hub model files. Nothing extra needs enabling. The next explicit download prepares `huggingface_hub==2.4.0` and `hf_xet==1.8.0` in a separate, versioned `xet-client` environment on the GPU host. This does not install packages into ComfyUI. Concurrent file workers share one locked client installation.

Xet fetches chunks in parallel within each file. High-performance mode is enabled, with range concurrency and reconstruction buffers bounded by the host's CPU affinity and available/cgroup memory. Four concurrent file workers remain. Explicit `HF_XET_*` environment overrides are preserved. Persistent chunk caching is disabled to avoid another weight-sized disk cache; the ordinary destination `.part` is the only full-file staging copy. These settings improve the transfer path; they cannot guarantee the host's advertised line rate against CDN, disk, CPU or shared-network limits.

The client emits ordered byte ranges into the existing contiguous `.part`. An HTTP partial can therefore continue through Xet at its real byte offset. Native parallel fetching never preallocates the model or reports buffered, unwritten chunks as installed bytes. Pinned revision, size and Hub LFS checksum are checked before the stream; the complete file still passes SHA256 before rename and the existing verified stamp. Corrupt content is rejected. A full disk produces an actionable error and retains the saved prefix.

The detached worker re-executes under the isolated client interpreter without changing its PID, start identity, job arguments or owned process group. SSH reconnection observes the same attempt; cancellation stops that group, including client preparation, and retains partial data. Already verified files need no client installation. No healthy model transfer has a whole-file time limit. Client package fetching uses pip's inactivity timeout/retries.

Only manifest entries with an immutable Hub commit and no explicit URL use this transport. Genuine non-Xet Hub objects, GitHub releases, custom URLs and legacy standalone facial packages retain the existing HTTP path. A failed Xet connection retries Xet from actual saved bytes; an access/pin failure does not silently switch transports. Existing saved transfers recover through their original runtime. This change never starts/resumes compute, starts a download on Generate, changes selected model files, restarts ComfyUI or rewrites historical generation recipes.

Public models need no Hugging Face or Xet token. An optional `HF_TOKEN` in the **GPU download process's environment** supplies Hub authentication/rate-limit benefits. Gated/private models additionally require that account to have access. This is not a new token field in Studio, and setting a local laptop variable alone does not forward it over SSH. The Hub token is excluded from CAS request headers; the native client obtains a scoped CAS token through the validated official Hub refresh route. Wrapped client errors omit signed URLs and credentials.

Validation includes nineteen new transport/lifecycle cases, the complete 403-check Python suite (one existing skip), 77 focused Studio download checks and typecheck. The exact pinned native client also downloaded a 540,217-byte public Xet fixture, then resumed it from a 12,345-byte prefix through the real managed worker and verified identical SHA256, journal and receipt. This is Mac client/protocol evidence, not Linux/GPU throughput measurement. No GPU operation, model-weight download on a rental, server reload or inference was performed. See the [validation receipt](validation/xet-model-downloads-20261108.json).
