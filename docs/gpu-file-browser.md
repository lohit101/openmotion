# GPU file cleanup

On the separate `feat/openjutsu-remotion` branch, Settings → Downloads → **Browse GPU files** opens a file browser on the currently connected managed rental. The storage-only milestone preserved the old renderer; the subsequent [OpenJutsu integration](openjutsu-remotion.md) now supplies the new Remotion screen. The Wan prototype is preserved in its own worktree.

Choose Model files, Uploaded media, Generated files, Temporary files, Recast workspace or ComfyUI installation. The first four use the existing managed models/data directories. The installation path comes from the active ComfyUI process beneath the workspace, falling back to bootstrap's saved installation record, never from a browser-supplied absolute path. The browser lists one directory at a time, directories first and files largest first, in pages of 300. It reads metadata, not model contents, and never recursively scans the drive or hashes large weights. A folder with more than 20,000 entries reports an error instead of returning a misleading partial list.

Any ordinary, singly-linked file in these locations can be explicitly deleted, including custom formats outside the download catalog. The confirmation shows the rental, exact path and measured file size. Each operation removes only the selected file; it does not recursively delete directories or also remove similarly named files. Links, special files and runtime/transfer locks remain read-only. The UI explains that non-catalog files cannot be recovered by a module download. Deleting installation files may require preparing the engine again; the model download button is not an OS/package recovery system.

Deleting a catalog dependency refreshes physical model inventory, so stale ComfyUI loader names cannot keep it marked installed. The affected module then offers its existing **Download Remotion** (or other module) action. That explicit action restores only missing files required by the selected settings to their pinned destinations, using the existing resume/checksum/retry behavior. Selection, deletion and inventory reads never automatically download files, resume compute or submit inference. Retired files remain removable without re-enabling retired downloads. Copies of media already downloaded onto the laptop are unchanged.

Both browsing and deletion bind to the connected instance and endpoint; a saved/offline inventory cannot authorize writes. The manager serializes deletions against model/setup work, blocks active/unresolved GPU work, releases idle cached models and rechecks ComfyUI's queue and the selected rental after awaited probes. The current small Python helper runs through the existing SSH connection without installing anything. It rechecks the remote queue and worker processes before deleting, traverses directory descriptors with `O_NOFOLLOW`, rejects linked targets and held download locks, and compares a metadata fingerprint against the exact listed file. A changed file requires a new selection. A missing file is an idempotent no-op; failed/unconfirmed requests are not automatically retried. Free disk space is measured again, rather than assuming logical file size equals reclaimed blocks.

Validation uses disposable local files and fake rental/transport fixtures. It covers changed files, traversal/links, held complete/partial download locks, exact-instance changes, busy/unknown queues and the delete → missing dependency → selected-only download cycle. An isolated headless browser exercised desktop/mobile navigation, actual temporary-file removal, confirmations, toast feedback, the missing-model Download Remotion state and offline behavior. No user file, real GPU, provider action, inference or model transfer was used. See the [validation receipt](validation/gpu-file-browser-20261107.json).
