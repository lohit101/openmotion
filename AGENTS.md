# Project workflow

- Keep this project in Git. Make a separate, focused commit after each completed bug fix or feature, with the relevant validation recorded. Do not rewrite existing commits unless the user asks.
- Commit source code, workflows, model/runtime manifests, documentation and small sanitized validation reports. Keep API/SSH credentials, `.local`, Studio databases, uploaded references/videos, generated media, model weights and raw GPU captures out of Git. Raw capture bundles belong under ignored `backups/`.
- Work offline whenever possible. The user controls pausing and unpausing the rented GPU. Capture what is needed before they pause; finish independent implementation and checks before requesting GPU validation. Do not automatically start/resume a paused instance or submit new paid test renders without the user's authorization.
- Model selection must account for the user's explicit preference for uncensored local models and model-matched LoRAs. Open weights, permissive licensing and a graph without content-filter nodes do not establish uncensored model behavior. Do not select a stock checkpoint solely for memory savings when that requirement is unverified. Distinguish publisher claims, encoder-only modifications and behavior actually tested on this setup. Do not add hosted moderation dependencies or prompt-blocking UI as a routine implementation choice.
- Healthy GPU setup has no elapsed-time stop. Slow setup shows a yellow warning/toast; actual failures show red messages/toasts and request a compute stop. Preserve downloaded models on failure. Keep manual instance stop/destroy controls available.
- GPU setup installs the runtime only. All model weights and feature adapters require explicit user download actions. Selecting a preset, connecting, refreshing availability or pressing Generate must never initiate a model download. Keep per-option controls, individual shared-model downloads, true transfer progress, resume/checksum checks and missing-file validation before paid submissions.
- For realism work, compare synchronized source/output frames and saved conditioning masks. Check scale, placement, occlusions, lighting and temporal consistency. Preserve originals and settings, distinguish measured results from hypotheses, and do not promise perfect realism from an untested change.
- In Character swap, the source video controls screen placement, apparent scale, framing and motion; the reference supplies character appearance/proportions. Preserve the source-relative reference preparation for new Studio jobs, its immutable per-job cache and pre-upload validation. Never silently change conditioning during continuation or automatically rerender a quality warning. Motion transfer has separate reference-scene semantics.
