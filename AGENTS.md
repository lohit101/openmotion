# Project workflow

- GPU discovery and new-rental preflight require a known download/ingress price of at most $0.005/GB, per the user's revised limit. Filter at the provider and locally, including favourite availability, and recheck the exact rental ask before spending. Keep management controls and cached models for existing rentals. Upload, storage and compute fees remain separate.

- Keep this project in Git. Make a separate, focused commit after each completed bug fix or feature, with the relevant validation recorded. Do not rewrite existing commits unless the user asks.
- Commit source code, workflows, model/runtime manifests, documentation and small sanitized validation reports. Keep API/SSH credentials, `.local`, Studio databases, uploaded references/videos, generated media, model weights and raw GPU captures out of Git. Raw capture bundles belong under ignored `backups/`.
- Work offline whenever possible. The user controls pausing and unpausing the rented GPU. Capture what is needed before they pause; finish independent implementation and checks before requesting GPU validation. Do not automatically start/resume a paused instance or submit new paid test renders without the user's authorization.
- Model selection follows the latest user preference: on 2026-10-26 the user explicitly accepted stock/non-NSFW models and prioritized visual fidelity and speed for production. Do not constrain this research or subsequent model selection to uncensored variants. Keep LoRAs matched to the exact model family and distinguish publisher claims from behavior actually tested on this setup. Open weights and permissive licensing do not establish uncensored behavior. Record material model/dependency licensing limits; do not add hosted moderation dependencies or prompt-blocking UI as a routine implementation choice.
- The latest overnight instruction (2026-10-26) authorizes research, implementation and paid GPU validation with a hard $0.70/hour compute ceiling; modest separately disclosed storage is allowed. This supersedes the earlier proposed $0.80/hour plan. Use one GPU at a time, preserve originals, report actual spend, and stop compute after validation. Do not leave a rental idling overnight or escalate above this ceiling. The three-minute target is unproven until measured on the complete workflow. The user accepts Viggle for private evaluation; record its licence separately from future hosted-service suitability. Healthy work still has no elapsed-time automatic stop.
- Healthy GPU setup has no elapsed-time stop. Slow setup shows a yellow warning/toast; actual failures show red messages/toasts and request a compute stop. Preserve downloaded models on failure. Keep manual instance stop/destroy controls available. User-authorized exception (2026-10-26): automatically stop and destroy a new, never-installed rental on explicit container failure, or after five minutes of repeated missing container status, unassigned direct ports and independently unreachable SSH. Recheck before cleanup, confirm deletion, retry unconfirmed cleanup and exclude that host for 24 hours. Never apply this to image loading with reported status, runtime/model installation, existing model disks or renders.
- GPU startup installs a blank ComfyUI engine without any model weights or sample media. This supersedes the earlier automatic Natural bundle preference at the user’s request on 2026-10-25. Use the small native amd64/arm64 CUDA base image and pinned PyTorch binary wheels. Models download only after an explicit action, using the exact files needed by the current settings; selection, refresh and Generate never download anything. Keep individual file controls and true byte progress, resume/checksum checks and missing-file validation before paid submissions. All LoRAs are optional and removable from the intended managed GPU, with active-render/transfer and path protections; core checkpoints/encoders remain outside LoRA deletion. Treat a sub-five-minute engine launch as a target on fast hosts, not a measured or universal guarantee. Do not conflate engine readiness with render readiness.
- For realism work, compare synchronized source/output frames and saved conditioning masks. Check scale, placement, occlusions, lighting and temporal consistency. Preserve originals and settings, distinguish measured results from hypotheses, and do not promise perfect realism from an untested change.
- In Character swap, the source video controls screen placement, apparent scale, framing and motion; the reference supplies character appearance/proportions. Preserve the source-relative reference preparation for new Studio jobs, its immutable per-job cache and pre-upload validation. Never silently change conditioning during continuation or automatically rerender a quality warning. Motion transfer has separate reference-scene semantics.
